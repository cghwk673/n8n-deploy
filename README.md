## 五步搭好 n8n：从空白服务器到编辑器

整个部署一共五步：装环境 → 建数据目录 → 启动容器 → 配域名和 HTTPS → 初始化账号。下面按顺序走。

### 第一步：连上服务器，装好环境

拿到 VPS 后用 SSH 登录（IP 和 root 密码在开通邮件里），系统选 Debian 12 或 Ubuntu 22.04 都行。接下来有两条路：愿意敲命令的，直接装 Docker；想省事的，先装 1Panel 这类服务器面板，后面的容器管理、反向代理和证书申请都有可视化界面，对纯新手友好得多。用面板的话，容器参数照下面的步骤填是一样的。

### 第二步：拉镜像、建数据目录

bash
mkdir -p /opt/n8n/data
docker pull n8nio/n8n


容器内的 `/home/node/.n8n` 存放着你的全部 Workflow、执行记录和第三方 API 凭证，对应宿主机的 `/opt/n8n/data`——以后备份就备份这个目录，它在，n8n 的数据就在。

### 第三步：启动容器

bash
docker run -d --name n8n --restart unless-stopped \
  -p 5678:5678 \
  -v /opt/n8n/data:/home/node/.n8n \
  -e GENERIC_TIMEZONE=Asia/Shanghai \
  -e N8N_RUNNERS_ENABLED=true \
  n8nio/n8n


常用环境变量对照：

| 变量 | 作用 |
| --- | --- |
| `GENERIC_TIMEZONE=Asia/Shanghai` | 定时触发类工作流用的时区 |
| `N8N_RUNNERS_ENABLED=true` | 新版将工作流执行与主进程分离的开关 |
| `N8N_HOST` / `WEBHOOK_URL` | 配好域名后加；前者填域名，后者带 https:// 协议头 |
| `N8N_PROXY_HOPS=1` | n8n 前面有几层反向代理就填几 |
| `N8N_SECURE_COOKIE=false` | 只在暂时用 IP:5678 访问时加，上了 HTTPS 就去掉 |

这里有个第一次部署最容易踩的坑：没有域名、先用 IP 访问测试时，如果登录页一直刷新进不去，多半是缺了 `N8N_SECURE_COOKIE=false`——n8n 默认只在 HTTPS 环境下种 Cookie。

### 第四步：域名解析、反向代理和 HTTPS

在域名商那里加一条 A 记录指向 VPS 的 IP，然后在 1Panel 里创建一个「反向代理」类型的网站（或用 Caddy），代理地址填 `http://localhost:5678/`——结尾的斜杠一定要有，否则编辑器的 WebSocket 连不上，画布状态不会实时刷新。证书用 Let's Encrypt 自动签发，勾上自动续签，不然三个月后就要手动折腾一次。

### 第五步：初始化账号

访问你的域名，填邮箱、姓名、密码创建 owner 账号，它就是 n8n 的超级管理员。

> **自建的 n8n 找不回密码。** 私有部署没有“忘记密码”邮件，账号丢了只能清空数据重装。创建完第一件事：把密码存进密码管理器，顺手把数据目录加进备份计划。

进设置把界面语言切成简体中文（新版本已内置多语言）；如果你的版本没有中文选项，可以挂载社区汉化包并加上 `N8N_DEFAULT_LOCALE=zh-CN` 环境变量。到此部署完成。

## 第一个工作流，和之后的日常维护

第一个工作流十分钟就能跑通：画布里加一个 Manual Trigger（手工触发），接一个 OpenAI 节点，动作选 Message a Model，凭证里填一个兼容 OpenAI 接口的服务密钥（比如硅基流动），模型选 Qwen3-8B 这类便宜型号，点测试就能看到返回。跑通之后把触发器换成 Webhook 或定时触发，它就是一个真正替你干活的自动化了。

日常维护就三件事：

1. **备份**：定期打包 `/opt/n8n/data`，或者直接在 VPS 面板做快照。
2. **升级**：`docker pull n8nio/n8n` 拉新镜像，`docker stop n8n && docker rm n8n` 停掉旧容器，再用原来的 run 命令启动。升级前先备份。
3. **安全**：防火墙只放行 22、80、443 端口；5678 不要直接暴露公网，访问统一走反代和 HTTPS。

**一台 VPS 只跑 n8n 是不是浪费？**
